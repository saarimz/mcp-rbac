# DX friction log (0.4 phase)

Problems found while building real servers and policies with mcp-rbac, and what changed because of them.

| # | Found while | Friction | Change |
|---|-------------|----------|--------|
| 1 | writing examples/policies/venue.yaml | `owner: tools: ["*"]` silently bypassed `refund_ticket`'s tool-wide `limits` (amount ≥ 0.01), so an owner could refund a negative amount. The TS declarative API has the same behaviour (only `allow` grants get tool limits). | Portable v1: a tool's `limits` are checked for **every** grant of that tool. Documented as a deliberate difference from the TS declarative API. |
| 2 | same | Limiting the length of an *optional* argument (`reason: {maxLength: 500}`) made it required (`missing:reason`). TS infers optionality from the zod schema; a YAML file can't. | Kept strict (fail-closed), but `optional: true` is now called out in the format doc and the schema description, and `check` output is shown in the quickstart. |
| 3 | writing examples/policies/devops.yaml | `service: {pattern: "[a-z][a-z0-9-]{1,40}"}` was rejected ("'-' must be escaped inside a class"). A trailing hyphen is idiomatic and every target engine (JS u-mode, Python `re`, Rust `regex`, Go RE2) treats a first/last `-` as literal. | Portable regex: `-` is literal as the first class member or right before `]`, in Rust, TS and Python (3-way tested); other unescaped `-` still rejected. |
| 4 | same | `version: {pattern: "v\\d+\\.\\d+\\.\\d+(-[a-z0-9.]+)?"}` (semver pre-release) was rejected as star height > 1. An *optional* group cannot cause nested unbounded backtracking. | A quantified group containing a quantifier is allowed when the outer quantifier's max is ≤ 1 (`?`, `{0,1}`, `{1}`); `(a+)*` / `(a+){2}` still rejected. Error text now says what is allowed. Spec notes polynomial backtracking + "pair pattern with maxLength". |
| 5 | running `mcp-rbac-core check` from scripts | printed nothing (exit 0): `process::exit` skipped the `BufWriter` flush. | Flush before exit. |
| 6 | differential fuzzing (conformance/difffuzz.py, P3) | The same YAML file loaded differently (or was rejected by only one language) in 7 classes: tabs, control/line-break characters (67/128 probes diverged), escaped surrogates, multi-line flow collections, YAML 1.1 `?`/`:` in PyYAML flow context, bare `?`/`-`, block scalars inside flow. A policy that means different things in different languages is a security bug. | Portable YAML profile, enforced identically in Rust/TS/Python (docs/policy-format.md "YAML subset"); value-level `yamlDoc` vectors (185 documents) in the corpus. Error messages say what to write instead. |
| 7 | same | Writing a JSON policy in a `.yaml`/stdin context went through the YAML parser (JSON ⊂ YAML 1.2 in theory, not in practice: multi-line JSON hits the flow rules). | A document whose first non-whitespace character is `{` is parsed as strict JSON, in every language. |
| 8 | same (adv vectors) | `{"tool":"t", …, "tool":"u"}` was decided as tool `u` (last wins) in all three engines; a gateway or log that reads the first key sees `t`. | Duplicate object keys rejected in request, `visible` and policy JSON (`invalid_input` / `invalid_request` / `policy_invalid`). |
| 9 | running the full TS suite on 2026-11-15 | `delegation.test.ts` hard-coded an expiry of 2026-11-15 02:00 ET and started failing at 02:00. | Test pins the Guard clock (`now`). |
| 10 | Python SDK 2.3 binding (P4b) | `@server.tool()` returning `dict` produced text-only results; `structuredContent` was missing, so redaction could not be checked on the structured channel. | Example server uses `@server.tool(structured_output=True)` with `-> dict[str, Any]`; documented in docs/polyglot.md. |
| 11 | Go binding (P4c) | Core `check` reports a bad policy as `{"error":"policy_invalid",...}`, not `{"ok":false}` as I assumed when writing the test; decision `redact` is a list of rule objects, not field names, and an over-typed Go struct failed to decode the decision on the first redacting call. | Go `Decision.Redact/Labels` are `[]json.RawMessage` (the core applies them); the wrapper only checks emptiness, like TS/Python. |
| 12 | Go binding (P4c) | The C ABI passes pointers as u32: correct on wasm32, silently truncating if someone links the crate natively. | `core/mcp-rbac-abi` compiles to nothing outside `target_arch = "wasm32"` (dependency is target-gated too). |
| 13 | rmcp binding (P4d) | rmcp 3.10 shapes results per negotiated protocol (strips `resultType` for pre-2026-07-28 peers) inside `ServerHandler`; a `Service`-level guard that answers denials itself skipped that and sent `resultType` to a 2025-06-18 peer. Found by driving the real binary with raw JSON-RPC. | Guard applies `strip_result_type_for_legacy_peer` / `fill_missing_cache_hints` to its own results; wire-shape test with a raw stdio client. |
| 14 | rmcp binding (P4d) | Workspace feature unification turns on serde_json `arbitrary_precision` + `preserve_order` (needed by the core for byte-identical numbers) for rmcp too. | No failure observed (5 e2e incl. numeric args and structured results); noted as a compatibility risk in docs/polyglot.md. |
| 15 | Python OTel tests (P5b) via the SDK's in-memory `Client` | **Real bug in the P4b Python guard:** the in-memory client negotiates MCP 2026-07-28, where `CallToolResult.resultType` is required, and the guard's own denial dict had none, so every denial became a server validation error. The stdio e2e tests missed it because `stdio_client` negotiates an older version. (Same class as row 13.) | Denials always carry `"resultType": "complete"` (legacy surfaces drop it via `extra="ignore"`); regression test on the modern protocol, verified to fail without the fix. TS SDK 1.32 stops at 2025-11-25, so TS isn't affected. |
| 16 | Python OTel | `trace.set_tracer_provider` works only once per process, so two test modules that each install a provider fight; and the Python client issues its own `tools/list` (output-schema validation), so "exactly one tools/list span" is wrong. | Session-wide `otel_spans` fixture in conftest; tests filter by span kind/scope. |
| 17 | TS OTel | `new SimpleLogRecordProcessor(exporter)` (pre-0.200 style) type-checks loosely in vitest and silently exports nothing with sdk-logs 0.223, which wants `{ exporter }`. | Fixed in tests; docs/otel.md shows the current form. |
| 18 | Go guard + OTel, found by the real-collector e2e (P5e) | **Real crash (DoS):** a `tools/list` with no `params` (the Python client sends exactly that) gives go-sdk middleware a typed-nil `*ListToolsParams` inside a non-nil `Params` interface. The telemetry path called `GetMeta()` on it, which panicked and **killed the server process**. The Go unit tests used the go-sdk client, which always sends `params: {}`. | `requestMeta` checks for typed nil. Raw JSON-RPC regression test `TestOtelRequestsWithoutParamsDoNotPanic`, verified to panic without the fix. |
| 19 | Go OTel (P5e) | go-sdk 1.8 doesn't expose the JSON-RPC request ID to middleware (unexported `idContextKey`), so `jsonrpc.request.id` can't be recorded. The negotiated version is available via `ServerRequest.ProtocolVersion()`, but the binding hadn't used it. | `mcp.protocol.version` is now set and asserted. The request id is a documented known gap. |
| 20 | TS OTel (P5e) | TS SDK 1.32 doesn't keep the negotiated protocol version anywhere public, so `mcp.protocol.version` was never set over stdio. The unit test didn't check it. | Feature-detected wrap of the outer `Server`'s `_oninitialize` captures the result's version; the attribute is omitted if the hook disappears. Test asserts it and was verified to fail without the hook. |
| 21 | TS test hygiene | A `define.test.ts` case writes `test/_deprecation_<pid>.ts` and deletes it in `finally`. A killed vitest run left one behind (found untracked). | Deleted; pattern added to .gitignore. |
